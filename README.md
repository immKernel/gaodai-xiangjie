目标读者：零基础、备考研的人。素材：樊启斌《高等代数典型问题与方法》第一章（题目与详解 PDF）。
产物：每个小节一个**离线可打开**的 HTML（公式预渲染成 SVG，不依赖 MathJax/Google Fonts，国内也能打开），通过 GitHub Pages 发布。

- 已完成：1.1（例1.1–1.14）、1.2（例1.15–1.37，含 21 张图）、1.3（例1.38–1.62，含 36 张图）。下一个小节是 1.4（例1.63 起，本书 PDF 第 32 页起，开头有一段“本原多项式/高斯引理/有理根判据”的说明，应写进 intro.t）。
  1.3 页面：<https://immkernel.github.io/gaodai-xiangjie/1.3.html>

## 1. 目录与命令

```
src/head.html            共用样式（单文件，亮/暗色，手机宽度可读）
src/sections.json        小节列表（用于 --publish 时页首互链）
src/<节>/meta.json       标题、输出文件名、发布文件名
src/<节>/intro.t         本节开头的“先弄懂几个词/小工具”卡片（用 @card 指令，卡片里也可以放图；旧写法 intro.html 仍兼容）
src/<节>/problems/NN.t   每题一个文件（紧凑语法，见 §3）；也兼容 NN.html（1.1 的老写法）
tools/build.js           构建脚本
tools/figs.js            文本式画图（SVG），由 build.js 调用（见 §3.1）
tools/cut_figs.py        把构建好的 html 里指定例题的图单独抽出来，便于截图检查：python3 tools/cut_figs.py 构建好的.html ex1-40,ex1-41 /tmp/t.html
tools/pdf_extract.py     无依赖的 PDF 文字提取（见 §2）
tools/verify_example.py  用 Fraction 手写的多项式运算，用来核对例题的计算结果
```

```bash
cd tools && npm install            # 只需要 mathjax-full
node tools/build.js 1.2            # 生成 1.2最大公因式与互素_详解.html（本地预览）
node tools/build.js 1.2 --publish  # 同时复制为 site/1.2.html（若无 site/ 目录则复制到仓库根目录），并在页首加“其他小节”链接
```
构建结束会打印 `TeX errors:` / `Unrendered:`，**这两行出现就说明有公式写错**；没有就可以放心。

## 2. 低成本生成题目：已验证有效的做法

成本主要是 AI 的输出 token 与读 PDF 的 token。以下是实际做完 1.2（23 题）总结的经验。

1. **不要把 PDF 当图片读。** 用 `python3 tools/pdf_extract.py book.pdf > out.txt` 一次性抽成文本，再用 `grep -a -n "例1.15"` 定位、`sed -n 起,止p` 只看需要的行（文件里有二进制字节，grep 必须加 `-a`）。每页开头有 `=== PAGE n ===`。目录里有“题号索引”，可以先确定一个小节包含哪些例题。
2. **抽出的文本会丢负号、分数和上下标是乱的**（例如 `x 4 +x 3  3x 2` 其实是 $x^4+x^3-3x^2$）。所以：先读解答的**思路**，再自己把式子**重新推一遍**，不要照抄。书中解答偶尔把负号弄丢（例1.26 的恒等式就是如此），必须自己核对。
3. **计算类的题（辗转相除、系数比较、特解）先用 Python 核对再写。** `tools/verify_example.py` 里有 `add/mul/pw` 和若干检查，几秒钟就能确认 $u_0f+v_0g=\gcd$ 之类的结果。比写完发现错了再改便宜得多。
4. **用紧凑语法 `.t` 写题，不要手写 HTML。** 每个 `<li><div class="step-body">…</div></li>`、每个 `<p>`、`<div class="check"><b>` 都由 `build.js` 展开，省掉大量重复标签（没有精确测量，但每个步骤/段落少写约 40–100 个字符的结构标签，且不容易漏闭合标签）。
5. **一个 Write 调用写一题，一次回复里并行发出多个 Write。** 不要把整节塞进一个文件，也不要为每题开子代理（子代理要重新读上下文，更贵）。
6. **不要用 Bash heredoc 写含大量 `$`、`\` 的长文本**：实际遇到过命令被安全检查误判而整条拦截。用 Write 工具写文件。
7. **构建后只看三件事**：`TeX errors`、`Unrendered`、有没有残留的 `&lt;b&gt;` / `**`（`grep -c`）。要看版式，用无头 Chromium 截一张图：
   `headless_shell --no-sandbox --disable-gpu --virtual-time-budget=15000 --screenshot=out.png --window-size=700,1800 file:///…html`
   （页面有 1–2 MB 的 SVG，**不加 `--virtual-time-budget` 会截到空白图**）。只截首屏即可，不要逐题截图。
8. **图要多配，但用指令生成，不要手写 SVG。** 用户反馈“图有点少不利于理解”，所以 1.3 平均每题 1–2 张图。手写 SVG 一张要几百 token，而 `@plot`/`@roots`/`@blocks` 等指令一张只要 2–8 行文字（见 §3.1），布局、配色、深色模式、手机缩放都由 `figs.js` 处理。画图前先问：这个图能让读者“看见”什么？（根的位置、公共因式块、次数大小、单位根、曲线相切……）没有答案就不画。
9. **发布通过 GitHub Pages**（小红书等平台不能直接分享 .html 文件）：`--publish` 后在仓库里提交推送即可。

## 3. 紧凑语法（.t 文件）参考

以 `@` 开头的行是指令，其余行是正文。正文规则：空行分段；`$$…$$` 独占行（可跨多行）为展示公式；`- ` 开头为列表；以 `<` 开头的行原样输出（表格等）；`**粗体**` 与 `<b>粗体</b>` 都可用；`[[1.24]]` 会变成指向“例 1.24”的链接；正文里的 `<`、`>` 会自动转义，**公式里直接写 `<` 即可，不需要 `\lt`**。

| 指令 | 含义 |
|---|---|
| `@ex 1.15 7` | 例号、原书页码（开头必须有） |
| `@prob` | 题目卡片（正文是题目） |
| `@idea 文字` | “一句话思路” |
| `@step0 标题` | 步骤 0：用具体小数字先试一遍（不编号，虚线圆圈） |
| `@step 标题` | 一个编号步骤，**一步只做一件事** |
| `@check 标题` | 绿色“验算”框（放在某个 step 里） |
| `@why 标题` | 黄色“为什么会这样想”框（放在某个 step 里） |
| `@book 标题` | 折叠的“对照原书”（可选，写原书的简短做法或补充说明） |
| `@sum` | “这题记住什么”（列表） |

### 3.1 画图指令（在 .t 里，放在某个 @step 后面，会嵌进该步骤；放在 @card 里则嵌进卡片）

每条指令第一行的文字是图注；后面的行是参数。图里的文字是纯文本（**不要写 `$`**），`x^2`、`r_1` 会自动变上下标（多字符用花括号 `x^{m+1}`），也可以直接写 Unicode（x²、f₁）。

| 指令 | 参数行 | 用途 |
|---|---|---|
| `@plot 图注` | `x a b` / `y a b`（范围，y 可省略）；`fn 表达式 \| 图例 \| 样式`（样式：空=蓝实线，`dash`=黄虚线，`g`=绿，`r`=红）；`pt x y \| 标签 \| b`（`b` 表示标签放点下方）；`vl x \| 标签`（竖虚线） | 函数曲线、重根相切、插值点。表达式用 JS 语法，`^` 自动转幂，如 `x^3-5*x^2+7*x-2`，乘号必须写 `*` |
| `@roots 图注` | `n 6`；`hi 1 2 4 5 \| 图例`（高亮第 k 个根，从 0 起算）；`conj`（共轭对连虚线）；`from re im \| 标签`（从该点向所有根连弦，用于“弦长乘积”） | 单位根、复平面上的根 |
| `@blocks 图注` | `名字: 块 块 块`（每行一个多项式，用块表示因式）；以 `=` 开头的行是结果行（绿色）；`legend a 文字` | 公因式 = 各行共有的块（蓝色高亮），一眼看出 gcd、互素、重因式 |
| `@venn 图注` | `gap 24`（两圆间距，小=几乎重合）；`LT`/`RT`（上方标题）；`L`/`M`/`R`（左/交/右区域文字，`\|` 换行）；`B`（底部说明） | 两个“公因式集合”相同 |
| `@bars 图注` | `mark 5 \| 说明`（红色竖虚线）；`标签 \| 数值 \| 颜色 \| 右侧文字`（颜色 a/b/c/d/box） | 次数比较、重数比较 |
| `@flow 图注` | 每行一条流程：`[a]框一 -{箭头上的字}> [b]框二 -> [c]框三`；一行太长会自动折行 | 证明路线、算法流程 |
| `@strip 图注` | 每行：`[a]项 \| [d]项 \| …`；`legend` | 分类/分堆（如按 m mod 6 分类） |
| `@synth 图注` | `c: 系数…`；下一行 `c:`（不写系数）表示用上一次的商继续除 | 综合除法表（数值自动算出） |

颜色代号：`a` 蓝（强调/公共）、`b` 黄（想法）、`c` 绿（结果/成立）、`d` 红（不成立/矛盾）。

## 4. 讲解风格（用户已认可，请保持）

- 先给“一句话思路”，再按步骤走；**每步只变一件事**，不跳步（展开、通分、换元都写出来）。
- 凡是能用具体数字验证的，用 `@step0` 或 `@check` 带一个小例子（如 $m=n=2$、$f=x^2-1$），这是最能让小白放心的环节。
- 出现关键套路时用 `@why` 说明“为什么会想到”。工具性结论放在 `intro.html` 里（1.2 里是 (A)–(E) 五个小工具），题目里用“工具 (D)”引用。
- 书里的证明如果有更简单的等价写法（例如 1.26、1.19），就用更简单的作为主线，原书做法放进 `@book`。
- 书里省略的前提（如 1.23 要 $f,g\ne0$，1.36 要 $h\ne0$）要点明并举反例。
- 结尾 `@sum` 写 2–3 条可迁移的结论。
- 文本用中文，公式用 `$…$` / `$$…$$`，不要使用 MathJax 之外的宏；`aligned`、`cases`、`vmatrix` 等 AMS 环境可用。

## 5. 已踩过的坑

- 在 `.t` 里 `@idea`、`@step` 等指令行后面的文字是“标题/首句”，正文从下一行开始（`@idea` 例外：同一行的文字就是正文）。
- `-x^2/6` 这类以负号开头的表达式没问题（脚本会处理），但 `2*-x` 这种“运算符后紧跟负号”不行，请加括号。
- MathJax 里不能用 `\textcircled`；要标号①②，请直接在正文里写 Unicode 的 ①②（不要放进 `$…$`）。
- 页面出现横向滚动，多半是某处有过宽的行内公式：把长公式拆成两个 `$…$`，或改成独占一行的 `$$…$$`（展示公式自带横向滚动）。已在 `head.html` 里把 main/section/.steps 的网格列设成 `minmax(0,1fr)`，不要改回 `1fr`。
- 构建脚本用 `[\d-]+` 从 `id="exN-M"` 取题号，所以每个 `.t` 文件第一行必须是 `@ex N.M 页码`。
- 链接 `[[1.24]]` 指向同一页面里的锚点；跨小节的引用不会生成链接（会变成断链），请直接写“例 1.x（见 1.1 节）”。
- 浏览器截图见 §2.7；仓库里的 `*_详解.html` 是构建产物，已在 `.gitignore` 里忽略，发布用的是 `index.html` 与 `1.2.html`。
